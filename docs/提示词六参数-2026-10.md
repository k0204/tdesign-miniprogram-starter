## 一、结论：只留这 6 个

| # | 参数 | 维度 id | 管辖的事 | 可选取值 |
|---|---|---|---|---|
| 1 | 景别 | `shot` | 主体占多大、留多少环境 | 10 |
| 2 | 机位 | `angle` | 相机放在哪、朝哪个方向 | 15 |
| 3 | 景深 | `dof` | 清晰到虚化的过渡范围 | 9 |
| 4 | 光位 | `lightDir` | 主光从哪个方向来 | 15 |
| 5 | 光质 | `lightQuality` | 光的软硬与明暗结构 | 16 |
| 6 | 后期 | `grade` | 成片的色彩与质感走向 | 24 |

保留的判据只有一条：**这个参数改的是「怎么拍」，而不是「拍什么」**。
图生图的输入已经决定了拍什么（人、衣服、场景、表情），能被提示词安全改动的只有拍摄方式本身。

## 二、砍掉的 6 个，以及为什么

| 维度 | 砍掉的理由 |
|---|---|
| 场景 `scene` | 改场景＝换背景，等于重画整张图，人物一致性最先崩。用户真正想说场景时，会写在自由描述里，那里还能带细节 |
| 天气季节 `weather` | 同上，且和场景强耦合；语料里 61% 是标注默认值，信息量低 |
| 前景 `foreground` | 语料里 95.5% 是「无前景遮挡」，等于这个维度实际只有一个有效取值 |
| 色温 `colorTemp` | 与后期、光质三重重叠。用户选「冷色温」+「暖调胶片」就是自相矛盾，模型只会挑一个执行 |
| 色调 `tone` | 同上，且与后期高度重叠；保留后期一个入口，判断标准更单一 |
| 情绪 `mood` | 形容词。模型接不住「温暖柔和」，但接得住「暖调胶片质感，轻微颗粒」——情绪已被后期吸收 |

**共同问题**：v5 里同一个视觉结果有三四条路径可以到达（色温 / 色调 / 后期 / 光质），用户选得越多，提示词里同义句越多，权重被稀释，改出来的东西反而不受控。

## 三、逐参数分析

### 1. 景别 `shot` — 前 20 个字里最重要的一句

景别决定画面信息密度：环境越多越像「故事」，越近越像「人像」。分成三族，按由远及近排列：

| 组 | 取值 | 进提示词的短语 |
|---|---|---|
| 大景 | 大远景 | 大远景，人物在画面里很小，环境才是主体 |
| 大景 | 远景 | 远景，人物全身与环境同框，环境占画面大部分 |
| 大景 | 环境人像 | 环境人像构图，人物约占画面三分之一，环境交代充分 |
| 中景 | 全景 | 全景，人物全身完整入画，头顶与脚下都留出余量 |
| 中景 | 七分身 | 七分身构图，取到膝盖以上 |
| 中景 | 中景 | 中景，取到腰部以上，手部动作入画 |
| 近景 | 近景 | 近景，取到胸口以上，肩线与表情是重点 |
| 近景 | 特写 | 特写，面部占画面主要部分 |
| 近景 | 大特写 | 大特写，只保留五官细节，画面被脸部填满 |
| 近景 | 局部特写 | 局部特写，只取手部或身体某一处细节 |

**为什么补**：v5 只有 5 档（全景/中景/远景/特写/近景），缺「环境人像」这个语料里占两成的主流档，也缺七分身、大特写、局部特写三档——用户想「框紧一点」时只能退到自由描述。
**风险**：景别改动越大，脸的重绘量越大。大远景→大特写是重构图，不是微调，身份一致性会掉。

### 2. 机位 `angle` — 高度定气质，方位定能看到多少脸

| 组 | 取值 | 短语要点 |
|---|---|---|
| 高低 | 平视 / 微俯 / 俯拍 / 顶俯 / 仰拍 / 贴地 / 航拍 | 从「镜头与眼睛同高」到「几乎垂直向下」，共 7 档高度 |
| 方位 | 正面 / 四分之三侧 / 正侧面 / 背面 / 过肩 | 相机相对人物转了多少度 |
| 随手拍 | 手机视角 / 自拍 / 镜面自拍 | 带生活感的机位，视角偏广 |

**为什么补**：v5 只有平视/手机/俯拍/仰拍/自拍 5 档，缺方位这一整个维度。而「稍微侧一点」恰恰是最常见的诉求——四分之三侧比正面更立体，又不丢脸。
**风险**：**背面机位与「锁定人物」天然冲突**——背对镜头时脸上什么都看不到。要背影可以，但别指望还认得出是谁；界面会在锁定区给出橙色提示。

### 3. 景深 `dof` — 控制「看人」还是「看环境」

| 组 | 取值 | 短语要点 |
|---|---|---|
| 虚实 | **强虚化** / **背景虚化** / 光斑虚化 / 轻微虚化 / 背景清晰 / 前后全清晰 | 从「只有眼睛清晰」到「前后都锐利」，6 档 |
| 特殊 | 前景虚化 / 微缩移轴 / 动态拖影 | 不是纯景深，但同属「谁清晰谁糊」的控制 |

**为什么补**：v5 只有 3 档，且 96.9% 的语料都是「大景深」。实际拍摄里浅景深是最常用的分离手段，只给 3 档等于没有选择余地。
**「模糊背景」放哪**：它不是新维度，属于**景深**。界面用「强虚化 / 背景虚化 / 轻微虚化 / 背景清晰」直接描述结果；进提示词的正文仍保留浅景深、大景深等摄影术语。想要更明显的背景模糊就选「强虚化」或「光斑虚化」。
**风险**：背景虚化会削弱背景可辨识度，如果用户同时选了场景类描述（在自由描述里写的），两者会打架——背景被糊掉了。

### 4. 光位 `lightDir` — 方向定阴影，阴影定立体感

| 组 | 取值 |
|---|---|
| 顺光 | 顺光 |
| 侧光 | 左前侧 / 右前侧 / 左侧 / 右侧 / 正侧光 |
| 逆光 | 左后逆光 / 右后逆光 / 逆光 / 剪影 |
| 上下 | 顶光 / 顶侧光 / 底光 |
| 无向 | 窗侧光 / 无向漫射 |

**为什么补**：v5 有「左侧光 / 右侧光 / 顺光 / 顶光 / 逆光 / 底光 / 侧光」，但「侧光」和「左/右侧光」重叠，实际只有 6 个有效方向。本版把方向拆成**前侧（45°）→ 正侧（90°）→ 后侧（135°）**三档，再补顶侧光，等于把摄影里的经典布光位补齐。
**快捷项取舍**：收起时只显示顺光 / 侧光 / 逆光 / 窗侧光 / 无向漫射，不同时铺左侧与右侧。用户需要指定阴影落向时，再展开选择左右方向。
**风险**：剪影和身份约束完全冲突（只剩轮廓），当成「剪影效果」用可以，别当人像用。

### 5. 光质 `lightQuality` — 软硬 + 明暗 + 光源类型

| 组 | 取值 | 说明 |
|---|---|---|
| 软硬 | 极柔漫射 / 柔光 / 半硬光 / 硬光 | 阴影边缘的锐利程度，4 档连续 |
| 明暗 | 高调光 / 低调光 / 聚光 | 画面整体的亮度结构 |
| 光源 | 黄金时刻 / 蓝调时刻 / 阴天散射 / 逆光眩光 / 穿雾光束 / 霓虹混合光 / 烛光 / 屏幕光 / 直闪 | 具体光源或清晰可见的光效，自带色温与衰减特征 |

**为什么补**：v5 只有柔光/硬光/霓虹混合光三项，等于把光质等同于「软硬」一个轴。实际上「低调光」和「柔光」是两个独立维度，可以同时成立。
**穿雾光束为什么单列**：参考样本中「光束」出现 11 次、丁达尔光出现 2 次，结果清晰可辨；它既不是单纯硬光，也不是镜头眩光。伦勃朗光、蝴蝶光在当前样本中没有出现，且可由现有侧光 / 顶侧光表达，因此不再增加术语入口。
**风险**：光源类（烛光、屏幕光、直闪）自带色偏，如果同时选了后期里的「日系清爽」，色彩会互相拉扯。建议光源类只选一个，且别再叠强调色偏的后期。

### 6. 后期 `grade` — 决定最终像什么片子

| 组 | 取值 |
|---|---|
| 写实 | 原片感 / 自然通透 / 商业精修 |
| 胶片 | 暖调胶片 / 冷调胶片 / 褪色胶片 / 粗颗粒 / 黑白银盐 / 柔和黑白 |
| 风格 | 复古港风 / 日系清爽 / 青橙电影 / 冷青悬疑 / 暖褐年代 / 银漂高反差 / 高级灰 / 冷调清透 / 暗调压缩 / 高反差 / 柔光光晕 / 浓郁饱和 / 低饱和胶片 / 拍立得 / 赛博霓虹 |

**为什么补**：v5 有 6 项，缺「原片感 / 商业精修 / 日系 / 电影感 / 柔和黑白 / 粗颗粒 / 低饱和 / 拍立得 / 赛博」等口语化高频风格。后期是用户最容易表达的诉求（「想要那种胶片感」），值得给最多选项。
**v9 的高级感收敛**：只新增「冷调清透」（语料 4.9%，冷而干净、细节锐利），其余全部靠改已有选项：
- 「低饱和」→「低饱和胶片」：语料 15% 的主流高级风格，补柔和低对比与颗粒
- 「柔焦朦胧」→「柔光镜」：高光轻微泛开、皮肤柔润，比单纯柔焦更像杂志片
- 「商业精修」补「高光细腻有光泽」：干净不等于平
- 暗角、奶油调、冷调高级灰不再单开：与现有风格重叠，或只是轻微后期，加了只让列表变长
- 「奶油虚化」不是单独的后期风格，因此不加进 `grade`；v13 将它做成柔光 + 背景虚化 + 肤质保护的跨参数配方
**v10 的高级后期核对**：不新增一排摄影术语，而是把可见结果补进已有方向：
- 「电影感」补高光暖、暗部青的分离色调，避免只写含糊的“电影感”
- 「褪色胶片」补抬黑位的哑光质感；「柔光光晕」补高光溢出，同时要求主体轮廓保持清楚
- 暗角在样本中常见，但它是可叠加的局部修饰；当前后期是单选，单列会迫使用户在“暗角”和整体调色之间二选一，因此暂不加入
- 银漂、交叉冲洗、径向模糊在当前样本中几乎没有出现，且分别与高反差、偏色风格、动态拖影重叠，因此不增加入口

**v11-v14 的推荐与微调**：推荐以女性自拍 / 写真人像为主，保留原有 13 种胶片、清透与电影方向，新增逆光补脸、逆光发光、奶油虚化、夜景直闪、霓虹拖影，共 18 种。推荐用于快速给出有辨识度的成片方向；选中后光线、虚化和后期因素自动填入，用户仍可逐项修改。逆光补脸偏自然修复，逆光发光才加入局部柔光光晕。

## 四、拼装与长度

```
copy.lead（生成意图）
→ 六因素短语，按 order 拼：景别 → 机位 → 景深 → 光位 → 光质 → 后期
→ 用户自由描述
→ 参考图说明
→ 锁定段（人物 / 场景 / 服装造型 / 姿势表情 中打开的项）
→ copy.tail（质量底线，必须最后）
```

- 段内用「，」连，段间用「。」分。短语与锁定文案里禁止出现句号，否则会把整句截断。
- 锁定段放在用户描述之后、质量底线之前：**越靠后的约束越不容易被前面的长句冲淡**。这是「人和场景被整张换掉」的主要防线。
- 实测：全选最优组合 106 字、整段（含默认锁人物+场景）287 字；3000 组随机组合最长 297 字。混元上限 8100、Agnes/Nexus 1900，余量充足。
- 零选择仍合法：不选任何因素时，提示词只剩 lead + 锁定段 + tail，等于「按原图重新出片」；把锁全关掉则只剩 lead + tail。

## 五、锁定不换（v7 新增）

6 个因素只管「怎么拍」，没有一条负责「拍的东西别动」。图生图最常见的翻车也不是调得不好看，而是 AI 顺着提示词把人物和背景一起重画了。所以锁定是**独立于因素的一层**：

| 锁 | 默认 | 锁住什么 | 进提示词的默认文案（节选） |
|---|---|---|---|
| 人物 | **开** | 身份 / 五官 / 脸型 / 发型 / 体型 / 年龄性别 | 严格保持原图人物的身份、五官比例、脸型、体型、发型与个人特征不变… |
| 场景 | **开** | 背景 / 地点 / 环境结构 / 空间关系 | 严格保持原图的背景、地点、环境结构与空间关系不变，不替换场景… |
| 服装造型 | 关 | 衣服 / 配饰 / 整体造型 | 严格保持原图人物的服装、配饰与整体造型不变… |
| 姿势表情 | 关 | 姿势 / 动作 / 表情 / 视线 | 严格保持原图人物的姿势、动作、表情与视线方向不变… |

设计取舍：

- **人物与场景默认锁**：这两项被换掉，用户一眼就知道「不是我的照片了」。服装/姿势默认不锁，避免用户只想换个风格时衣服也动不了。
- **文案可编辑**：页面上的笔进入编辑，可加「保留脸上的痣」「不要磨皮过度」这类默认里没有的要求；改过的文案存本地 `aiimage_lock_prefs_v1`，配置升级按 id 保留，点「恢复默认」回到配置值。
- **开关也可记忆**：同一把锁的开关与文案一起存，下次进来还是用户上次的设定。
- **冲突只提示、不替用户改**：背面机位 + 人物锁会提示面部辨识风险；强虚化、动态拖影会提示背景细节减少，但场景锁仍要求保留环境结构；局部特写则会提示画面缺少环境。锁和因素都是用户的明确意图，模型会按更靠后的锁定段执行。
- **AI 建议同步边界**：锁定段会作为 `keepHint` 发给提示词顾问，锁的变化也会进建议缓存 key，避免拿旧锁的候选去写新提示词。

## 六、使用建议（写给用户看的）

1. **一次只动一两个参数**。全选 6 项等于把重构图、换光线、换调色一起做，人物最不像。
2. **参数之间别互相打脸**：剪影 / 背面机位 与「锁定人物」冲突；黑白后期 与 色温类光质冲突；浅景深 与「锁定场景」冲突。
3. **说不清的用自由描述**。参数是给人「少打字」用的，不是限制——底部输入框可以写完整的一段话。
4. **默认锁着人物和场景**。如果这次就是想换背景/换造型，先在「锁定不换」里关掉对应项，再选因素或写描述，否则提示词会自相矛盾。

## 七、维护

```bash
# 改完 config/prompts/aiImage.factors.js（version +1）
node .workbuddy/scripts/verify-aiimage-menu.mjs     # 结构/锁定/拼装/3000 组随机/坏配置拒收
node .workbuddy/scripts/build-prompt-config.mjs     # 生成 .workbuddy/out/aiImage.factors.json
node .workbuddy/scripts/upload-prompt-config.mjs    # 上传云存储，热更新生效
```

界面按 `option.group` 自动分组，新增取值只要带上 `group` 就会排在对应族里，不用改页面。
锁定项新增只要带 `id/name/phrase/defaultOn` 就会自动出现在「锁定不换」区；冲突提示目前按 `person` / `scene` 两个 id 写在前端，新增其他锁不需要改提示。
