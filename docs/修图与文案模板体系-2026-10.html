这两件事必须分开做。修图是色彩工程，可以用确定性算法做到零失真、百毫秒、可量化验收； 文案是内容运营，价值在于"选"而不是"生成"。把它们塞进同一套模板体系是错的， 但可以用同一条用户路径串起来：修好图 → 选一句话 → 自动套版式 → 审图。

01先说结论

  1. 变白不能交给生图模型。重绘后脸型、痣、双眼皮宽度都在变，用户第一眼"不像我"就流失；而且每次出片肤色不一致，连前后对比都做不了。
  2. 变白的真实机制是降黄，不是提亮。实测冷白皮档：肤色亮度 +13.4%，色温（R−B）+15.8 个单位下降。视觉上"白"主要来自 R−B 被压掉。
  3. 全局提亮一定烧掉浅色衣物。实测 19.72% 的像素被推成纯白，面积正好等于白衬衫。必须上肤色蒙版，否则主推档一用就废。
  4. 文案让用户直接选，不要生成。库是精选过的、可运营的、与版式配色绑定的；生成是慢的、不稳定的、还要过内容合规。
  5. 两条线共用一条路径：修图定"图"，文案定"话"，版式模板定"怎么摆"，审图定"能不能发"。

02修图：三级分工，AI 只做最后那一档

把"变白变美"拆成三件事，越往前越确定、越往后越有风险：

层级做什么实现风险
色彩　默认开变白、通透、降黄、氛围调sharp 本地，百毫秒零失真
质感　默认开轻磨皮、补锐、颗粒median / blur / sharpen低
AI 精修　默认关五官微调、发丝、光影重塑图生图 edits身份漂移

AI 档必须配闸门：输出前跑 facesim ≥ 0.85，低于阈值直接判失败、回退到色彩档结果。用户宁可少一点效果，也不能收到一张"不像自己"的照片。

03三次失败，和最后跑通的方案

这部分是本次最有价值的东西——不是"设计了几套参数"，而是参数被实测证伪了三次，最后才定下来。

失败一：蓝通道增益 v0.1

做法是"提蓝通道 = 降黄"，看起来对。但蓝增益同时在提亮，和 brightness 叠加后，浅色衣物成片爆掉：

B2 冷白皮把 19.75% 的像素推到纯白。这不是参数没调好，是模型错了——色温和亮度耦合在一起，没法独立调。

失败二：gamma 提亮 v0.2

改法是"色温用亮度中性的三通道矩阵，提亮用 gamma 保护高光"。理论完美，实测：

传入 gamma肤色区亮度变化
2.2171.3−0.6%
2.0171.3−0.6%
1.8171.3−0.6%
1.6171.3−0.6%
1.4171.3−0.6%

输出像素完全一致。原因：sharp.gamma() 对已解码的 sRGB JPEG 不生效，只对 raw / 未标定输入有意义。当时六个预设看起来有亮度差异，其实全部来自 tone 和 contrast，冷白皮只有 +2.8%，根本撑不起"显白最明显"的标签。

跑通：brightness 标定 + 肤色蒙版 v0.4

换成 modulate({ brightness })，它的行为是线性的、可标定的：

brightness肤色区提亮高光溢出
1.04+4.6%0%
1.06+6.9%0%
1.08+9.2%0%
1.10+10.9%0.23%
1.12+13.2%0.48%

规律：每 +0.01 ≈ 肤色区亮度 +2.3%。这条曲线让参数从"试出来的"变成"算出来的"。

但 brightest 抬到 1.095 时，白衣服又爆了。于是加肤色蒙版：全局先算出目标图，再用蒙版只把肤色区贴回去。两种模式的实测对比：

预设全局 Δ肤色全局溢出蒙版 Δ肤色蒙版溢出
B0 自然光+2.8%0%+2.7%0%
B1 通透感+8.4%0.3%+8.2%0%
B2 冷白皮+13.5%19.72%+13.4%0%
B3 奶油肌+12.5%19.68%+12.4%0%
B4 胶片感+2.8%0%+2.8%0%

效果几乎没损失（13.5% → 13.4%），溢出直接归零。18 组参数的超标数从 6 组降到 0 组。

上排 B0 自然光 / B1 通透感 / B2 冷白皮　下排 B3 奶油肌 / B4 胶片感 / B5 日落暖。肤色区（上椭圆）逐档变冷变亮，白衣服（下椭圆）在蒙版模式下始终保住原色。

实现上有个坑必须写下来：蒙版必须写成 RGBA。blend: 'dest-in' 读的是 alpha 通道，单通道灰度 PNG 的 alpha 恒为 1，合成出来等于没遮罩——我第一版就是这么错的，数据上表现为"蒙版模式和全局模式结果一模一样"。

还有个产品级细节：只修脸会让"脸白了身子还黄"，画面割裂。所以蒙版的 alpha 不是 0/255，而是肤色区 255、非肤色区 76（30% 弱补偿），羽化 4px。加了这层弱补偿后溢出仍是 0%。

预设给人看的一句话适合Δ肤色Δ色温强度
B0 自然光几乎看不出修过日常 / 证件照+2.7%−2.11.015
B1 通透感不白，但干净室内 / 阴天+8.2%−6.01.045
B2 冷白皮 主推显白最明显自拍 / 黄皮+13.4%−15.81.095
B3 奶油肌柔、软、有光泽人像 / 母婴+12.4%−11.11.080
B4 胶片感不显白，但显贵街拍 / 旅拍+2.8%−9.00.980
B5 日落暖反向操作，加暖旅拍 / 傍晚+6.0%+23.61.020

三档强度（light / standard / strong）只调 brightness 与色温，不碰其他参数——这样"再亮一点"是可预期的一小步，不会突然换风格。

交互红线（写进 JSON 的 neverDo）：不给用户看 brightness / tone / saturation 这类参数名；不做「美白强度 0–100」滑块；不在未选预设时默认套最重档。滑块会让人误以为要懂参数，是这类功能最大的流失点。

05文案：用户直接选，不生成

你要的"把旅行、心情、爱情的语句整理成模板，用户直接选"，这个方向是对的。五个理由：

为什么选 > 生成

  • 速度：选是 0 秒，生成要等 3–8 秒，还要重试
  • 质量下限：库里的每一句都被筛过，生成必出烂句
  • 风格一致：库有 theme / tone 结构，天然能匹配版式与配色
  • 可运营：加一条 = 全量用户多一个选择，不用等模型迭代
  • 合规：不碰 AI 生成文本的内容风险

结构：主题 × 语气

一级 主题 决定配色，二级 语气 决定版式。12 种组合，覆盖绝大多数分享场景。

扩展机制（后续加内容不用改代码）

  • 新增只填 theme / tone / main / sub，配色和版式由 12 组 outfitMatrix 自动决定，不用逐条配
  • 下线用 status=offline 软删除，已有作品引用仍能正常渲染
  • 某个语气在线不足 4 条时，前端隐藏该 chip，不展示空列表
  • 生成式作为"再来一句"的长尾补充，但主路径永远是选

06串起来：一条路径，四件事

选照片→选修图预设→选一句文案→自动套版式→审图打分→发布

关键点：用户全程不做设计决策，只做三次点选。版式和配色由"文案的主题 + 语气"自动带出来，这是文案库必须带 theme / tone 字段的原因——它不只是分类，是排版指令。

// 一次选择，链路自动串起来
const item = copyLibrary.pick(theme='travel', tone='clear');
const outfit = copyLibrary.outfitMatrix[`${theme}.${tone}`];
// → { templateId: 'T6-scene-overlay', paletteId: 'P5-morandi' }
const photo = beauty.apply(presetId='B2-cool-white', level='standard');
canvas.render({ photo, template: outfit.templateId, palette: outfit.paletteId, slots: { title: item.main, subtitle: item.sub } });

07审图怎么接这两条线

上一版 16 条规则管的是"分享图长得好不好看"。加了修图和文案库后，要补两组：

规则组判定不过时说什么
R1修图自然度修图前后肤色区 ΔL ≤ +18%，且 Δ(R−B) 在 −25~0 之间修过头了，皮肤会显假
R2修图自然度高光溢出 ≤ 2%，且白区纹理方差不低于原图 60%白衣服已经糊成一块，换轻一档
R3修图自然度背景与肤色色温差 ≤ 8 个单位（防"脸白身子黄"）脸和脖子不是一个色，把背景补偿加上
R4修图自然度AI 精修档 facesim ≥ 0.85这张不太像你本人，建议退回色彩档
W3文案库所用文案在当前 theme/tone 下 status=online，且未超过 maxChars（内部校验，不面向用户）
W4文案库文案主句与账号近 5 篇的主句相似度 ≤ 0.7这句你最近用过了，换一句

R3 是这次实测直接催生的规则。只修脸不修背景，肤色和背景的 R−B 差会拉开，中景/半身照尤其明显——这条规则不设的话，用户自己看不出问题但会觉得"怪"。

三个需要你拍板的：
1. 修图默认停在哪个预设？建议 B1 通透感（最安全），B2 冷白皮做成"推荐"角标引导。默认 B2 会让"不像我"的风险前置。
2. 文案要不要允许用户改？建议允许改字，但改完仍走 maxChars 校验，否则模板会被撑破。不允许改的话复用率会掉。
3. AI 精修档开不开？建议先不开。它是唯一的身份漂移来源，等 facesim 闸门在真实样本上验证过再放。
