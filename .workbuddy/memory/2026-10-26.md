## AI 修图页「引擎切换条没了」排查（pages/aiImage）

用户报「图片 ai api 选项没有了」，截图顶部只剩上传虚线框。排查结论：**引擎条没被删，是被 .page 的滚动带走了**。

- 数据侧完好：Node 里跑 onLoad，`data.engines` 3 项、`engine.emptyTip='原图直传，最大 10MB'`（截图里正好显示这句，反证 engine 有值）。
- 像素反推：截图 navbar 底 y=44，虚线框顶 y=46；按 less 应是 44+8(page pad)+8(stage pad)+33(stage__head) = 93，差 47px ≈ 引擎条自身 46px → 页面滚动位置正好把引擎条滚出视野。
- 根因：`.page` 是 `height:calc(100vh-nav)` + `overflow-y:auto` 的滚动容器，引擎条是它第一个子元素，跟着内容一起滚。
- 修法：wxml 加 `.shell` 包一层，`<div class="shell">引擎条 + <div class="page">…</div></div>`；less 里 `.shell` 接管 CSS 变量和定高，`.page` 改 `flex:1 + height:auto + min-height:0`，引擎条 `padding:16rpx 32rpx 12rpx`（32 = 原 page 24 + engine 8，视觉不变）。
- 否决 sticky 方案：`.page` 有 `-webkit-overflow-scrolling:touch`，iOS 下 sticky 会失效。
- 校验：wxml 标签配对脚本 PASS、less 大括号收支 0、`verify-aiimage-page.mjs` 44 项全过。真机效果交用户微信预览确认。

## 真凶：包体积超限导致预览一直上传失败（用户手机上一直是旧包）

「引擎选项没了」的真正原因不是代码，是**预览包从来没上传成功**，手机上打开的是上一次成功的旧包。

- `auto_preview` 第一次报：`main package source size 4442KB exceed max limit 2048KB`。
- 构成：`.npm-cache` 单文件 2.1MB（隐形大头）+ `tdesign-miniprogram` 全量 + 业务代码 1.2M。
- 修：
  1. `project.config.json` 的 `packOptions.ignore` 加 `.npm-cache` / `docs` / `mock` 目录，加 `.py` / `.csv` / `.jsonl` 后缀（`docs` 里 20MB 语料、`mock` 22 个 js）。
  2. `node .workbuddy/scripts/tdesign-prune.mjs --apply`：tdesign 3.2M(du) → 1.4M，删 43 个未引用组件 + 334 个 .d.ts/.md。
- 结果：`auto_preview` 成功，**主包 1372783B / 总 1609191B / aiImage 分包 86135B**。
- 教训：**报「明明改了没生效」先跑一次 auto_preview 看能不能上传**，超限是静默失败，症状和代码 bug 一模一样。

顺带保留的改造：aiImage 页拆 `.shell`（定高）+ 引擎条常驻 + `.page`（flex:1 滚动区），避免引擎条被内容滚动带走。

### 修正：mock 不能排除（启动崩溃）

把 `mock` 加进 `packOptions.ignore` 后，真机报 `module 'mock/index.js' is not defined, require args is './mock/index'`（app.js:2 → app.js:3 的 `import Mock from './mock/index'`）。

- 原因：`config.js` 里 `isMock: true`，mock 是运行期依赖，不是开发期资料。`app.js` 顶层静态 import，排掉就必崩。
- 处理：从 ignore 里删掉 `mock`（保留 `docs` / `.npm-cache` / `.py` / `.csv` / `.jsonl`）。
- 重新 auto_preview：主包 1133692B / 总 1370100B，仍远低于 2048KB。
- 判定被排除目录是否安全：`grep -rn "目录名/" --include=*.js` 看有没有运行时引用（注释里的 URL 不算）。

## 最终结论：t-navbar 默认 fixed 且不占位，把引擎条整条盖住了

前面所有猜测（滚动、数据为空、旧包）都不是主因。用运行时数据坐实：

```
wx.createSelectorQuery() 量出来的真实位置（模拟器 430×834）
.shell        top 0     height 834     ← 从屏幕最顶开始，不是从导航栏下面
.engine       top 0     height 67      ← 整条躺在导航栏底下
.engine__item top 11    width 130      ← wx:for 正常渲染了 3 个，dataset.id = hunyuan
.stage__head  top 76    height 28      ← 「原图」标题也在，同样被盖
```

- 根因：`miniprogram_npm/tdesign-miniprogram/navbar/props.js` 里 `fixed: {value: true}`、`placeholder: {value: false}`。`<t-navbar title="AI 修图" left-arrow />` 因此是 fixed 悬浮、零占位，页面内容从 y=0 开始，顶部 ~99px（状态栏 + 48）全被盖。
- 修：`<t-navbar ... placeholder />` + 布局改成 `page { display:flex; flex-direction:column; height:100vh; overflow:hidden }`、`.shell { flex:1; min-height:0 }`。删掉 `data.pageStyle` 和 onLoad 里 `statusBarHeight + 44` 的硬算（算出来 98px，实际导航栏 99~102px，差几像素就是切一条）。
- `verify-aiimage-page.mjs` 的断言也从「pageStyle 含 100vh」换成布局契约：wxml 必须带 `placeholder`、必须有 `.shell`、不许再出现 `style="{{pageStyle}}"`。44 项全过。
- 遗留：`pages/{dataCenter,leaveMessage,login,loginCode,my/info-edit,release,search,setting}` 的 t-navbar 同样缺 `placeholder`，顶部内容大概率也被盖，待统一处理。
