# 2026-10-25

## 留言板：锁屏改为「当场隐藏」，不再等回到前台

用户反馈：锁屏回来内容还在，且是 onShow 刷新后才看不到 —— 期望锁屏那一刻就隐藏。

根因：
- 原来只有 `wx.onAppHide` 一条通道在 `lockBoard()`，页面级 `onHide` 只 `stopSync()` 不上锁（旧记录明确写着"内部跳页不上锁"）。
- 真机锁屏先走页面 onHide；部分安卓灭屏时 App 级回调迟到甚至不来 → `unlocked` 仍为 true → 回前台 `onShow` 里 `pullNew()` 跑了一遍，表现就是"打开后刷新"。

改法（pages/leaveMessage/index.js）：
- 新增 `handleBackground()`，页面 `onHide` 与 `wx.onAppHide` 都走它，`lockBoard()` 幂等。
- `onShow` 用 `_leftAt` 算离开时长，超 `RELOCK_AFTER_HIDE = 1000ms` 先锁 **再 return**，绝不下落到 pullNew/startSync。
- 选图豁免改走 `isPickingMedia()`（`_mediaPicking` 或 `_mediaDoneAt` 在 `PICK_GRACE = 1500ms` 内），解决 complete 与 onShow 先后顺序的机型差异。
- 加会话令牌 `_session`：`lockBoard` 时 +1，`loadFirst`/`loadMore`/`pullNew`/`send` 回执落地前比对令牌 + `unlocked`；`ingest`/`onWatchChange` 首行判 `unlocked`。防止锁屏瞬间在途请求把数据灌回已清空页面。
- `tryUnlock` 里 `await loadFirst()` 后再判一次 `unlocked` 才 `startSync()`。
- 已知代价：切到微信内其他界面回来也会锁，草稿/选图会丢（锁屏与切走无法区分，隐私优先）。

顺带把 `.workbuddy/memory/MEMORY.md` 从 27KB 压到 ~15KB（去重 + 合并「锁屏上锁」新结论）。
