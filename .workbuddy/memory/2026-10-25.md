## 留言板：锁屏改为「当场隐藏」，不再等回到前台

用户反馈：锁屏回来内容还在，且是 onShow 刷新后才看不到 —— 期望锁屏那一刻就隐藏。

根因：
- 原来只有 `wx.onAppHide` 一条通道在 `lockBoard()`，页面级 `onHide` 只 `stopSync()` 不上锁（旧记录明确写着"内部跳页不上锁"）。
- 真机锁屏先走页面 onHide；部分安卓灭屏时 App 级回调迟到甚至不来 → `unlocked` 仍为 true → 回前台 `onShow` 里 `pullNew()` 跑了一遍，表现就是"打开后刷新"。

改法（pages/leaveMessage/index.js）：
- 新增 `handleBackground()`，页面 `onHide` 与 `wx.onAppHide` 都走它，`lockBoard()` 幂等。
- `onShow` 用 `_leftAt` 算离开时长，超 `RELOCK_AFTER_HIDE = 1000ms` 先锁 **再 return**，绝不下落到 pullNew/startSync。
- 选图豁免改走 `isPickingMedia()`（`_mediaPicking` 或 `_mediaDoneAt` 在 `PICK_GRACE = 1500ms` 内），解决 complete 与 onShow 先后顺序的机型差异。
- 加会话令牌 `_session`：`lockBoard` 时 +1，`loadFirst`/`loadMore`/`pullNew`/`send` 回执落地前比对令牌 + `unlocked`；`ingest`/`onWatchChange` 首行判 `unlocked`。防止锁屏瞬间在途请求把数据灌回已清空页面。
- `tryUnlock` 里 `await loadFirst()` 后再判一次 `unlocked` 才 `startSync()`。
- 已知代价：切到微信内其他界面回来也会锁，草稿/选图会丢（锁屏与切走无法区分，隐私优先）。

顺带把 `.workbuddy/memory/MEMORY.md` 从 27KB 压到 ~15KB（去重 + 合并「锁屏上锁」新结论）。

## 实测混元图生图的 prompt 真实上限（结论：8192，且与耗时无关）

用户问「480 是生图的限制吗」，查证后发现 500/480 都是自己拍的值，遂实测。

过程与坑：
- 第一次用 `await wx.cloud.callFunction` 写测法，8192/3000 都拿到 `timeout waiting for automator response` —— **那是 automator 通道自己的响应超时，不是云函数失败**，白等 3 分钟且分不清原因。
- 第二次改成「发起后立即返回、Promise 挂 `globalThis`、隔 75s 再读」，才拿到真数据。
- 8500 字用于验证护栏：738ms 返回「提示词最多 8192 字」，说明护栏在调模型之前，不产生费用。

实测（真实垫图 + 真实出图）：
| prompt 长度 | 结果 | 耗时 |
|---|---|---|
| 600 字 | 成功 | 8.4s |
| 3000 字 | 成功 | 11.1s |
| 8192 字 | 成功 | 9.4s |
| 8500 字 | 被自家护栏拒绝 | 0.7s |

**关键结论：耗时与 prompt 长度无关**（8-11s 波动）。所以「长提示词会拖慢生成」这个担心不成立，真正的风险是偶发长尾（首次调用可能 >60s，会撞 callFunction 硬限）。

修改：
- `cloudfunctions/imageToImage/index.js`：`MAX_PROMPT_LENGTH` 500 → **8192**（注释写明实测数据）
- `pages/aiImage/providers.js`：混元 `maxPromptLength` 480 → **8100**（留 92 字余量）
- `pages/aiImage/promptOptions.js`：`MAX_PROMPT_LENGTH` 480 → 8100，并注明它是遗留常量、页面实际用 `engine.maxPromptLength`

顺带确认免费额度来源：`HY-Image-v3.0-I2I-ToB-v1.0.1` 是「小程序成长计划」二期资源包里的生图模型，**10 万张 / 6 个月 / 仅限小程序与云开发服务端**。模型本身支持 0-3 张参考图，我们只传 1 张（单图精修定位）。

### 删除死代码 isPromptTooLong / MAX_PROMPT_LENGTH

- `pages/aiImage/editPresets.js`：删掉 `isPromptTooLong()`（全项目无人调用），import 里去掉 `MAX_PROMPT_LENGTH`，再导出列表只留 `ANCHOR_PHOTO` / `CONSTRAINT_TAIL`。
- `pages/aiImage/promptOptions.js`：删掉 `MAX_PROMPT_LENGTH` 常量（原本 480 → 曾改成 8100）。
- 删除理由：它固定按单一常量判超长，而混元 8100 / Agnes·Nexus 1900 各不相同，谁拿去用都会误伤。页面判断一律走 `engine.maxPromptLength`。
- 回归：`simulator_open_page` 重开 `pages/aiImage/index` → 注入图 + 选效果 → `promptDigits='255 字'`、`parts=['基础','改动','保留','质量']`、size `880x1168`，与删除前完全一致；console 无 error。grep 已确认无残留引用。

## aiImage 生图菜单改造：固定套餐 → 多维度选择

原结构 5 类功能 × 4 个固定选项 = 20 个套餐，只能整选一个，表达不了组合意图。现改为「功能 × 2-5 组维度」。

- `issue` 画面问题 7 值（自动判断/逆光/硬光/顶光/平光/底光/无问题）

- `texture` 质感微调 6 值（多选，最多 2）

**四个设计决定（都有具体理由）**
1. **光位与画面问题互斥**：指定目标光位时 `buildMods` 跳过 issue——两者都在重做照明，叠一起模型会收到两套矛盾指令。

3. **单选维度点两次不清空**，回落到第一项。清空会让指令突然为空、按钮变灰，用户无法理解。
4. **`auto` 只负责技术缺陷，不负责风格**。原来写"去灰、正白平衡"会和「自然清透」撞车。

**必须给 relight 加 `balance` 选项**：不给的话「保持原光位」让整个维度等于没选，拼不出任何指令。

**改动文件**：dimensions.js（新）、editPresets.js（buildEditPrompt 收 selection + selectionKey 做缓存 key）、promptOptions.js（**删掉 20 个套餐的 options**，只留能力元信息）、index.js（selection/dimensions/ready 替代 picked/optionsView）、index.wxml（横滑 chips 多组）、index.less（+130 行 dims 样式）。

## 00:45 Agnes「队列满」的真实原因：云函数配错了 key

用户问「超时设了 240s，为什么不到 100 秒就超时；我们买了 token plan，不该满」。

### 第一层：不是超时

`cloud_fn_info` 三个函数 timeout 都是 **240**（agnesImage / agnesImageWorker / nexusImageWorker）。库里最近两条失败记录：

| 创建 | 耗时 | error |
|---|---|---|
| 23:37 | 107.4s | `image queue is full, please retry later` |
| 23:35 | 79.8s | `image queue is full, please retry later` |

是 `queue is full`，不是 timeout。80-107 秒收场的机制：`TOTAL_BUDGET_MS=200s` + 退避 `[4,8,15,25,40]s` 最多 6 次 + **弃试条件「剩余预算不足 100s 就不发新请求」**（一次出图 93s，剩余不够就是白烧）。79.8s 那次是 6 次尝试用完，107.4s 那次是某次请求在 Agnes 侧排队 80s 才回 503，一次吃掉大半预算。

### 第二层：真正的根因是 key 不是同一把

默认 host 是 `api.agnes-ai.cn`，可被 `AGNES_API_HOST` 覆盖。加诊断 action 后实测线上：

```
worker: host=apihub.agnes-ai.com  hostFromEnv=true  key=sk-OTqVy…(51)  model=agnes-image-2.5-flash
docs/prompt-tool: host=apihub.agnes-ai.com        key=cpk-2mNF…(52)
```

**两把不同的 key**。用 **cpk-（token plan 那把）** 打同一 host 实测：**HTTP 200，10.6 秒出图**，零排队。所以 `sk-` 那把走的是共享队列 —— 买了 plan 也没用，因为线上根本没用那把。

另：`api.agnes-ai.cn` 用 cpk- 打是 **401「无效的令牌」**；两站（`.cn` 国内站 / `apihub...com` 国际站）各自计费与限流，key 不通用。
